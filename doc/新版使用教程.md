# 新版 DuiLib 使用教程

本文面向本次改造后的 DuiLib，默认使用 VS2026、C++20、Win32/x64。

## 准备环境

本机推荐使用：

```powershell
D:\Microsoft Visual Studio\18\Community\MSBuild\Current\Bin\MSBuild.exe
```

打开解决方案：

- DuiLib 主库：`DuiLib.sln`
- 编辑器：恢复后的 `DuiDesigner` 项目

## 构建配置

DuiLib 只保留四个配置：

- `Debug`：Unicode DLL 调试版，输出到 `bin` 或 `bin\x64`，代码生成使用 `/MTd`。
- `Release`：Unicode DLL 发布版，输出到 `bin` 或 `bin\x64`，代码生成使用 `/MT`。
- `lib_debug`：多字节静态库调试版，输出到 `Lib` 或 `Lib\x64`，代码生成使用 `/MTd`。
- `lib_release`：多字节静态库发布版，输出到 `Lib` 或 `Lib\x64`，代码生成使用 `/MT`。

DuiLib 的 PCH 和编译 PDB 会写入各自 `$(IntDir)`，同一份 DuiLib 在编辑器和应用项目之间交替构建时不会共用旧预编译头。

```powershell
# DLL 发布版 Win32
& "D:\Microsoft Visual Studio\18\Community\MSBuild\Current\Bin\MSBuild.exe" DuiLib.sln /m /p:Configuration=Release /p:Platform=Win32 /v:minimal

# 静态库发布版 x64
& "D:\Microsoft Visual Studio\18\Community\MSBuild\Current\Bin\MSBuild.exe" DuiLib.sln /m /p:Configuration=lib_release /p:Platform=x64 /v:minimal
```

也可以使用自动编译脚本：

```bat
build\build_all.bat
build\build_all.bat all
build\build_all.bat duilib Release Win32

rem 自动化调用时关闭脚本末尾暂停
cmd /c "set DUILIB_BUILD_NO_PAUSE=1&& build\build_all.bat designer Release Win32"
```

## 三档控件 profile

当前默认启用轻量版、标准版和全量版全部控件。开关集中在 [UIProfile.h](../DuiLib/Core/UIProfile.h)：

```cpp
#define DUI_CONTROLS_LIGHT    0x01
#define DUI_CONTROLS_STANDARD 0x02
#define DUI_CONTROLS_FULL     0x04
#define DUI_CONTROLS_FLAG (DUI_CONTROLS_LIGHT | DUI_CONTROLS_STANDARD | DUI_CONTROLS_FULL)
```

常用组合：

- 轻量版：`#define DUI_CONTROLS_FLAG DUI_CONTROLS_LIGHT`
- 标准版：`#define DUI_CONTROLS_FLAG (DUI_CONTROLS_LIGHT | DUI_CONTROLS_STANDARD)`
- 全量版：`#define DUI_CONTROLS_FLAG (DUI_CONTROLS_LIGHT | DUI_CONTROLS_STANDARD | DUI_CONTROLS_FULL)`

项目预处理器中不再定义控件 profile 宏。

## 引入头文件

应用代码继续使用统一入口：

```cpp
#include "DuiLib/UIlib.h"
```

默认可直接使用全量控件；如果裁剪档位，`UIlib.h` 不会包含被裁剪控件头，XML 构建器也不会创建被裁剪控件。

## 使用 tstring 和 UTF-8 文本接口

新版保留旧 `SetText`、`GetText`，返回值已经统一为 `tstring`。同时新增 UTF-8 标准字符串接口，用于业务数据和外部文本交换。

`tstring` 在多字节配置下使用 `std::string`，在 Unicode 配置下使用 `std::wstring`。旧的 `CDuiString` 不再作为公共类型使用；少量历史兼容类名会暂时保留，但内部实现优先使用 C++20 标准库容器。

```cpp
DuiLib::CButtonUI* button = new DuiLib::CButtonUI();
button->SetNameUtf8("btn_ok");
button->SetTextUtf8("确定");

DuiLib::tstring nativeText = button->GetText();
std::string name = button->GetNameUtf8();
std::string text = button->GetTextUtf8();
```

管理器也可以使用 UTF-8 名称查找控件：

```cpp
DuiLib::CControlUI* ok = paintManager.FindControlUtf8("btn_ok");
```

常用元数据和属性也可以直接使用 UTF-8：

```cpp
button->SetToolTipUtf8("提交当前表单");
button->SetUserDataUtf8("action=submit");
button->SetAttributeUtf8("height", "32");
button->ApplyAttributeListUtf8("bordersize=\"1\" bordercolor=\"#FFD1D5DB\" ");
```

## 控件文本绑定

可以把控件文本绑定到 `DuiUtf8String`。本地窗口字符串继续由 `tstring` 承担，绑定通道使用 UTF-8，方便业务层保持统一编码。

```cpp
DuiLib::DuiUtf8String status = "准备就绪";

DuiLib::CLabelUI* label = new DuiLib::CLabelUI();
label->BindTextUtf8(status);

status = "正在处理";
label->RefreshTextBinding();

label->SetTextUtf8("处理完成");
label->CommitTextBinding();
```

绑定规则：

- `BindTextUtf8(DuiUtf8String&)` 保存引用，调用方必须保证字符串生命周期长于控件。
- `RefreshTextBinding` 把数据刷新到控件。
- `CommitTextBinding` 把控件文本写回数据。
- 复杂场景可以使用 getter/setter 版本接入业务模型。

## SwitchButton

`SwitchButton` 属于轻量版控件，默认自绘，不依赖图片资源。点击、空格和回车都会切换状态，并发送 `click` 和 `selectchanged` 通知。

```xml
<SwitchButton name="notify" width="52" height="26" selected="true" ontext="开" offtext="关" />
```

代码中可按开关或复选框风格使用：

```cpp
auto* sw = static_cast<DuiLib::CSwitchButtonUI*>(paintManager.FindControl(_T("notify")));
if (sw != nullptr) {
    sw->SetCheck(true);
    bool enabled = sw->GetCheck();
}
```

## 多语言

当前主库提供 `CMultiLanguageUI`。语言文件使用 UTF-8 `key=value` 格式，控件 `name` 对应文本，`name_tip` 对应提示文本。

```ini
title=示例窗口
title_tip=这是窗口标题
search=查询
```

```cpp
DuiLib::CMultiLanguageUI lang;
if (lang.LoadFromFile(_T("lang_zh_cn.ini"))) {
    lang.Apply(&paintManager);
}
```

切换语言时重新加载另一个语言文件并再次 `Apply` 即可。值中支持 `\n`、`\r`、`\t` 转义；语言文件中缺失或空值不会覆盖现有文本。

## profile 使用建议

优先选择轻量版：

- 普通设置窗口
- 表单录入
- 列表展示
- 简单工具面板
- 小型业务客户端

选择标准版或全量版：

- 需要树形资源管理：至少使用标准版
- 需要 GIF、IP 地址或滚动文字：至少使用标准版
- 需要富文本编辑：使用全量版
- 需要高级列表编辑：使用全量版

## 使用 DuiDesigner 检查 XML

编辑器路线当前恢复为 `DuiDesigner`，非 MFC `DuiEditor` 暂停。`DuiDesigner` 继续保留 MFC 框架，并与新版 DuiLib 保持一致：

- 使用 `tstring`，不再依赖 `CDuiString`。
- 支持 Win32 和 x64。
- 使用 C++20 / VS2026 编译。
- 设计器始终显示全量控件清单。
- 不再提供 ActiveX、WebBrowser、Flash、Animation、AnimationTabLayout、ColorPalette、Loading、Ring 等已移除控件。
- 旧 XML 中的 `GifAnimEx`、`IPAddressEx` 应迁移为 `GifAnim`、`IPAddress`。

构建设计器：

```powershell
& "D:\Microsoft Visual Studio\18\Community\MSBuild\Current\Bin\MSBuild.exe" DuiDesigner\DuiDesigner.vcxproj /m:1 /p:Configuration=Debug /p:Platform=Win32
& "D:\Microsoft Visual Studio\18\Community\MSBuild\Current\Bin\MSBuild.exe" DuiDesigner\DuiDesigner.vcxproj /m:1 /p:Configuration=Release /p:Platform=Win32
```

设计器始终面向全量控件清单。Win32 输出在 `bin`，x64 输出在 `bin\x64`；默认编译验证使用 `Release|Win32`。

## 不再支持的能力

新项目不要再使用以下控件。ActiveX、WebBrowser、Flash 相关源码已经从新版主库移除；其余删除控件也不会进入 profile 和 DuiDesigner 控件清单。

- `ActiveX`
- `WebBrowser`
- `Flash`
- `Animation`
- `AnimationTabLayout`
- `ColorPalette`
- `Loading`
- `Ring`

如果旧项目使用了这些控件，应先改成轻量版或全量版现有控件组合，再迁移到新版库。
